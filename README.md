# ORBIT // ENTERPRISE

![ORBIT](logo.png)

ORBIT is a local, end-to-end enterprise data and decision intelligence platform. It covers simulated multi-source data, ingestion, quality gates, a Spark curation step, analytics, ML models, risk scoring, optimization, decision recommendations, a FastAPI backend, a Java integration service and a React + TypeScript decision intelligence web application (Phase 2). There is no chatbot: every answer in the UI is traced to stored data, models and rules.

## Quick start (Windows PowerShell, from the project root)

```powershell
. .\scripts\env.ps1                 # puts the portable tools from .tools on PATH
.\scripts\orbit.ps1 versions        # prints the toolchain versions
.\scripts\orbit.ps1 db-start        # starts portable PostgreSQL 17 on port 55432
.\scripts\orbit.ps1 migrate; .\scripts\orbit.ps1 seed
.\scripts\orbit.ps1 pipeline        # all 11 stages (add -Regenerate for fresh data)
.\scripts\orbit.ps1 test            # pytest suite
.\scripts\orbit.ps1 api             # FastAPI on http://127.0.0.1:8000/api/v1
.\scripts\orbit.ps1 java            # Java integration service on http://127.0.0.1:8081
.\scripts\orbit.ps1 web-install     # npm install (cache in .tools) + Playwright chromium into .tools\ms-playwright
.\scripts\orbit.ps1 web-test        # eslint + tsc + vitest
.\scripts\orbit.ps1 web-build       # tsc + production build to apps\web\dist
.\scripts\orbit.ps1 web-preview     # serves the build on http://127.0.0.1:4173 (proxies /api to :8000)
.\scripts\orbit.ps1 e2e             # Playwright journeys (needs api and web-preview running)
.\scripts\orbit.ps1 screenshots     # real screenshots into docs\screenshots
.\scripts\orbit.ps1 bi-export       # CSV datasets + schema.json into data\bi for Tableau / Power BI / QlikView
.\scripts\orbit.ps1 web-dev         # Vite dev server with hot reload
```

Do not pipe these commands through `2>&1` in Windows PowerShell 5.1: npm and Node write warnings to stderr, and the redirect turns them into terminating errors.

All tools live in `.tools\` (gitignored). Nothing is installed system-wide. Copy `.env.example` to `.env` and set the local database values.

## Web application

The app lives in `apps/web` (React 18, TypeScript, Vite, Recharts, React Router). It is organized as follows:
- `src/services/http.ts` is the only module allowed to call `fetch`. ESLint enforces this rule.
- `src/components/ui` holds the design-system primitives: Table, Tabs, Drawer/Modal, ChartContainer, Select, DateRange, states.
- `src/features/<page>` has one folder per screen.

Every view has loading, error (with retry), empty and success states.

The pages are:
- Landing
- Overview
- Intelligence (drill-down)
- Anomaly Explorer
- Forecasts
- Risk
- Operations
- Optimization (runs the real Julia/JuMP/HiGHS model through the API)
- Scenario Lab
- Decision Center (each recommendation has a "Why?" chain from the recommendation back to the forecast, model output, metric and dataset)
- Data Quality
- Models
- System

The global filters (date range, region, business unit, customer segment, product, incident category; each page shows only the filters it applies) persist in the URL and in localStorage. The top bar has a global search. Exports (CSV and a Markdown risk report) are generated by the API from the same data the page shows. Risk and status are always written as text (LOW, MEDIUM, HIGH, CRITICAL; Healthy, Watch, Unhealthy), never shown by colour alone.

Screenshots: `docs/screenshots/01-landing.png` to `14-system.png`. They were captured on the MSI laptop by `orbit.ps1 screenshots` against the live API.

BI and KPI governance: `docs/bi/` and `docs/kpi-governance.md`.

See `docs/` for the architecture, data model, pipeline, ML, decision, optimization, API and technology notes, plus `PROJECT-CONTEXT.md` for the current verified state.

All data is synthetic, and the metrics describe models trained on simulated data.
